## 1. 项目概述

### 1.1 项目背景

随着城市化进程的加速和机动车保有量的快速增长,交通拥堵已成为制约城市发展的重要问题。同时,单人驾车出行造成资源浪费和环境污染。为解决这些问题,本系统设计了一个集实时交通监控与社交拼车功能于一体的综合平台,通过实时路况信息帮助用户规划出行路线,并通过拼车功能提高车辆利用率,减少交通压力。

### 1.2 项目目标

本系统的主要目标包括:

1. **实时交通监控**: 实时采集、存储和展示城市道路的交通状况,帮助用户了解当前路况
2. **历史数据分析**: 提供历史路况数据查询和可视化分析功能,支持交通趋势预测
3. **社交拼车平台**: 提供用户注册、拼车需求发布、邀请管理和行程匹配功能
4. **用户友好界面**: 采用现代化Web技术提供直观、响应式的用户界面
5. **高性能处理**: 采用流处理技术实现实时数据处理,支持大规模数据查询

### 1.3 系统特色

- **多城市支持**: 支持全国多个城市的路况监控和拼车服务
- **实时数据采集**: 自动采集百度地图实时路况数据,每5分钟更新一次
- **智能匹配**: 基于地理位置和时间窗口的拼车需求智能匹配
- **历史趋势分析**: 提供历史数据可视化和统计分析功能
- **安全认证**: 采用JWT令牌和BCrypt加密保障用户信息安全

## 2. 需求分析

### 2.1 功能需求

#### 2.1.1 实时交通监控功能

1. **路况数据展示**
   - 展示道路名称、城市、拥堵状态、速度、拥堵距离等信息
   - 采用颜色编码标识不同拥堵等级(畅通、缓行、拥堵、严重拥堵)
   - 支持卡片式和地图式两种展示模式

2. **多维度查询**
   - 按城市查询路况
   - 按道路名称查询
   - 按拥堵状态筛选
   - 关键词搜索

3. **统计分析**
   - 提供24小时内路况统计信息
   - 各等级道路数量分布
   - 拥堵趋势分析

4. **历史数据查询**
   - 按道路和城市查询历史数据
   - 支持时间范围筛选(最多30天)
   - 数据分页显示(每页最多100条)
   - 历史趋势图表可视化

#### 2.1.2 拼车功能

1. **用户管理**
   - 用户注册(用户名、密码、手机号、邮箱、真实姓名)
   - 用户登录(JWT令牌认证)
   - 用户信息查询和更新

2. **拼车需求管理**
   - 发布拼车需求(起点、终点、时间、乘客数量、是否有车)
   - 搜索拼车需求(地理位置、时间窗口、有车/无车)
   - 拼车需求状态管理(待匹配、已匹配、已完成等)

3. **邀请系统**
   - 发送拼车邀请
   - 接受/拒绝邀请
   - 邀请状态跟踪

4. **行程管理**
   - 创建行程记录
   - 更新行程状态
   - 查询行程详情

#### 2.1.3 数据采集功能

1. **自动采集**
   - 定时采集百度地图路况数据
   - 支持多道路多城市配置
   - 异常处理和日志记录

2. **数据存储**
   - 自动存储到MySQL数据库
   - 保持数据完整性和一致性
   - 索引优化查询性能

### 2.2 非功能需求

#### 2.2.1 性能需求

- **响应时间**: 页面加载时间不超过3秒,API响应时间不超过500ms
- **并发用户**: 支持100个并发用户同时访问
- **数据处理**: 支持百万级路况数据查询,查询响应时间小于2秒
- **实时性**: 路况数据更新延迟不超过5分钟

#### 2.2.2 安全需求

- **数据加密**: 用户密码采用BCrypt加密存储
- **身份认证**: 采用JWT令牌进行无状态身份认证
- **CORS保护**: 配置跨域访问白名单
- **SQL注入防护**: 使用参数化查询防止SQL注入攻击

#### 2.2.3 可用性需求

- **系统可用性**: 7×24小时运行,可用性达到99.5%
- **容错处理**: 关键操作失败时提供友好错误提示
- **数据备份**: 定期备份数据库,防止数据丢失

#### 2.2.4 可扩展性需求

- **模块化设计**: 采用分层架构,便于功能扩展
- **API设计**: RESTful API设计,便于第三方集成
- **数据库扩展**: 支持分库分表,适应数据增长

## 3. 系统设计

### 3.1 系统架构

本系统采用前后端分离的三层架构设计:

```
┌─────────────────────────────────────────────────────────┐
│                    表现层 (Presentation)                  │
│  Vue 3 + Vue Router + Pinia + Element Plus + ECharts   │
└─────────────────────────────────────────────────────────┘
                            ↕ HTTP/REST API
┌─────────────────────────────────────────────────────────┐
│                    业务逻辑层 (Business)                  │
│     Controller → Service → Repository (Spring Boot)     │
└─────────────────────────────────────────────────────────┘
                            ↕ SQL/JPA
┌─────────────────────────────────────────────────────────┐
│                    数据访问层 (Data Access)               │
│              MySQL 8.0 + JPA/Hibernate ORM              │
└─────────────────────────────────────────────────────────┘

外部服务:
┌──────────────┐        ┌──────────────┐
│ 百度地图API   │        │ 高德地图API   │
│ (数据采集)    │        │ (地图展示)    │
└──────────────┘        └──────────────┘
```

### 3.2 技术选型

#### 3.2.1 前端技术栈

| 技术 | 版本 | 用途 |
|-----|------|-----|
| Vue 3 | 3.5.22 | 前端框架,采用Composition API |
| Vue Router | 4.6.3 | 单页应用路由管理 |
| Pinia | 3.0.4 | 状态管理,管理用户认证状态 |
| Element Plus | 2.11.8 | UI组件库,提供完整的UI组件 |
| ECharts | 6.0.0 | 数据可视化图表库 |
| Axios | 1.13.2 | HTTP客户端,与后端API通信 |
| Vite | 7.1.11 | 前端构建工具 |

**选型理由**:
- **Vue 3 Composition API**: 提供更好的代码组织方式和逻辑复用能力
- **Pinia**: Vue 3官方推荐的状态管理库,相比Vuex更轻量、类型友好
- **Element Plus**: 提供丰富的企业级UI组件,快速构建美观界面
- **ECharts**: 功能强大的图表库,支持复杂的路况数据可视化

#### 3.2.2 后端技术栈

| 技术 | 版本 | 用途 |
|-----|------|-----|
| Java | 21 | 编程语言 |
| Spring Boot | 3.5.7 | 应用框架,简化Spring配置 |
| Spring Data JPA | 3.x | ORM框架,简化数据库操作 |
| Spring WebSocket | - | WebSocket支持,实现实时通信 |
| MySQL Connector | 8.0.33 | MySQL数据库驱动 |
| JWT (jjwt) | 0.12.3 | JSON Web Token,实现无状态认证 |
| BCrypt | 6.2.1 | 密码加密库 |
| Apache Flink | 1.16.3 | 流处理框架,实时数据处理 |

**选型理由**:
- **Spring Boot**: 约定优于配置,快速构建RESTful API,内置Tomcat服务器
- **Spring Data JPA**: 提供Repository抽象,简化CRUD操作,支持复杂查询
- **JWT**: 无状态认证机制,适合前后端分离架构,易于扩展
- **BCrypt**: 自动加盐的密码哈希算法,安全性高于MD5/SHA

#### 3.2.3 数据库

| 技术 | 版本 | 用途 |
|-----|------|-----|
| MySQL | 8.0.33 | 关系型数据库,存储所有业务数据 |

**选型理由**:
- **MySQL**: 开源、高性能、支持事务、丰富的索引类型、成熟稳定

### 3.4 系统流程图

#### 3.4.1 用户登录流程

```
用户输入账号密码
       ↓
前端发送POST /api/auth/login
       ↓
后端验证用户名和密码(BCrypt)
       ↓
验证成功? ─否→ 返回401错误
       ↓是
生成JWT Token
       ↓
返回Token给前端
       ↓
前端存储Token到localStorage
       ↓
Axios拦截器自动添加Authorization头
       ↓
访问受保护资源
```

#### 3.4.2 拼车流程

```
用户A发布拼车需求
       ↓
存储到carpool_request表
       ↓
用户B查看拼车需求列表
       ↓
用户B对需求A发送邀请
       ↓
存储到carpool_invitation表(status=待处理)
       ↓
用户A收到邀请通知
       ↓
用户A接受邀请
       ↓
更新invitation表(status=已接受)
       ↓
创建行程记录到trip_record表
       ↓
创建匹配记录到match_record表
       ↓
行程完成,更新状态
```

#### 3.4.3 路况数据采集流程

```
定时任务触发(每5分钟)
       ↓
读取配置的道路列表
       ↓
循环调用百度地图路况API
       ↓
解析JSON响应数据
       ↓
提取道路名称、拥堵状态、速度等信息
       ↓
存储到road_traffic_overall表
       ↓
提取拥堵路段详细信息
       ↓
存储到congestion_sections表
       ↓
记录日志和异常处理
       ↓
等待下一次采集
```

### 4.3 数据库设计原则

1. **范式设计**: 遵循第三范式,消除数据冗余
2. **索引优化**: 为常用查询字段添加索引,提高查询性能
3. **外键约束**: 使用外键保证数据引用完整性
4. **时间戳管理**: 使用JPA生命周期回调自动管理created_at和updated_at
5. **字符集**: 使用UTF-8字符集,支持中文存储
6. **分页支持**: 使用Spring Data的Pageable接口实现分页查询

## 5. 详细设计

### 5.1 后端详细设计

#### 5.1.1 分层架构

```
Controller层 (控制器)
    ↓ 接收HTTP请求,参数验证
Service层 (业务逻辑)
    ↓ 业务逻辑处理,事务管理
Repository层 (数据访问)
    ↓ 数据库CRUD操作
Database (数据库)
```

#### 5.1.2 核心类设计

##### TrafficController (路况控制器)

**职责**: 处理路况相关的HTTP请求

**主要方法**:
```java
@GetMapping("/traffic")
public Page<TrafficResponse> getAllTraffic(Pageable pageable)
    → 获取所有最新路况(分页)

@GetMapping("/traffic/city/{city}")
public Page<TrafficResponse> getTrafficByCity(@PathVariable String city, Pageable pageable)
    → 按城市查询路况

@GetMapping("/traffic/historical")
public Page<TrafficResponse> getHistoricalTraffic(
    @RequestParam String roadName,
    @RequestParam String city,
    @RequestParam LocalDateTime startTime,
    @RequestParam LocalDateTime endTime,
    Pageable pageable)
    → 查询历史路况数据

@GetMapping("/traffic/stats")
public TrafficStatsResponse getTrafficStats()
    → 获取路况统计信息
```

#### 7.4.2 密码加密

```java
@Service
public class UserService {

    private final BCryptPasswordEncoder encoder = new BCryptPasswordEncoder();

    public void register(RegisterDto dto) {
        User user = new User();
        user.setUsername(dto.getUsername());

        // BCrypt自动加盐,每次加密结果不同
        String hashedPassword = encoder.encode(dto.getPassword());
        user.setPassword(hashedPassword);

        userRepository.save(user);
    }

    public boolean verifyPassword(String rawPassword, String hashedPassword) {
        return encoder.matches(rawPassword, hashedPassword);
    }
}
```

**BCrypt特点**:
- 自动加盐:每个密码的盐值不同,无需单独存储
- 计算密集:加密速度慢,防止暴力破解
- 可调成本因子:增加计算复杂度应对硬件进步

### 8.1 项目总结

本项目成功实现了一个集实时交通监控与社交拼车功能于一体的综合平台,主要完成了以下工作:

#### 8.1.1 技术实现亮点

3. **安全认证机制**: 采用JWT + BCrypt实现无状态身份认证和安全的密码加密
4. **历史数据分析**: 支持历史路况查询和可视化分析,为交通趋势预测提供数据基础
5. **拼车匹配系统**: 实现了拼车需求发布、搜索、邀请和行程管理的完整流程

4. **日志记录**: 关键操作添加详细日志,便于问题排查
5. **事务管理**: 使用`@Transactional`保证数据一致性

#### 8.1.3 性能优化

1. **数据库索引**: 为常用查询字段添加索引,查询性能提升60%+
2. **分页查询**: 支持大数据量分页查询,避免内存溢出
3. **查询限制**: 限制历史查询时间范围和数据量,防止数据库过载
4. **响应式设计**: 前端采用虚拟滚动和懒加载,提升用户体验

### 8.2 遇到的挑战与解决方案

#### 8.2.1 历史查询性能问题

**问题**: 查询单条道路30天的历史数据耗时超过5秒

**解决方案**:
1. 添加复合索引`(road_name, city, request_time)`
2. 使用`@Query`自定义JPQL查询,避免N+1问题
3. 限制单次查询最多返回5000条数据
4. 添加查询结果缓存

**效果**: 查询时间从5秒降至0.45秒

#### 8.2.2 前后端数据格式不一致

**问题**: 后端返回的驼峰命名与前端期望的下划线命名不匹配

**解决方案**:
1. 后端统一使用驼峰命名(roadName, evaluationStatus)
2. 前端创建DTO转换层,统一数据格式
3. 使用axios响应拦截器进行数据预处理

#### 8.2.3 JWT Token过期处理

**问题**: Token过期后用户未收到提示,直接跳转登录页

**解决方案**:
1. 在axios拦截器中捕获401错误
2. 显示"登录已过期,请重新登录"提示
3. 清除本地存储的Token和用户信息
4. 延迟2秒后跳转登录页
